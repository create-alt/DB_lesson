Docker / PostgreSQL 基本操作

3.2.1 定着確認（13問）

Q1. Docker では、「コンテナ」を雛形として「イメージ」を作成する。この説明は適切か答えよ。
【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（イメージを雛形としてコンテナを作成する）。
Q2. hoge:3.14 という Docker イメージから、 hoge-fuga というコンテナを作成するためのコマンド (起動はしない) を答えよ。
答え: docker container create --name hoge-fuga hoge:3.14 （省略形: docker create --name hoge-fuga hoge:3.14）
Q3. hoge:3.14 という Docker イメージを Docker Hub からプルするコマンドを答えよ。
答え: docker image pull hoge:3.14 （省略形: docker pull hoge:3.14）
Q4. hoge-fuga という Docker コンテナ (停止中) を削除するためのコマンドを答えよ。
答え: docker container rm hoge-fuga （省略形: docker rm hoge-fuga）
Q5. ローカルにダウンロード済みの Docker イメージの一覧を表示するコマンドを答えよ。
答え: docker images （または docker image ls）
Q6. Windows で docker images を実行したところ、Docker Engine に接続できないエラーが表示された。まず何を確認すべきか答えよ。
答え: Docker Desktop が起動済みで、ステータスが「Running」になっていること。
Q7. Docker イメージの指定 postgres:18.6 において、 postgres と 18.6 はそれぞれ何を表すか答えよ。
答え: postgres はイメージの名前、 18.6 はタグ (バージョン) を表す。
Q8. Docker コンテナの作成時に、環境変数 POSTGRES_DB に playground という値を設定するためのコマンドオプションを答えよ。
答え: -e POSTGRES_DB=playground
Q9. docker container create 実行時に返される「コンテナID」とはどのような識別子か。また全員同じIDになるか答えよ。
答え: Docker がコンテナごとに自動割り当てする64文字の16進数識別子。全員異なるIDになる。
Q10. 長いコマンドを複数行に分けて入力するとき、行末に付ける記号を PowerShell、Bash、コマンドプロンプト (cmd.exe) の順に答えよ。
答え: PowerShell: バッククォート (`)、Bash: バックスラッシュ (\)、コマンドプロンプト: キャレット (^)
Q11. Docker の Dockerfile はどのような役割か選べ。
【選択肢】❶ カスタマイズしたイメージを作成するための設計図 / ❷ コンテナを作成するたびに必ず用意するファイル
答え: ❶ カスタマイズしたイメージを作成するための設計図（既存イメージを使うだけなら不要）。
Q12. pg18 という停止中コンテナが存在する状態で docker container create --name pg18 postgres:18.6 を実行するとどうなるか。
答え: コンテナ名の重複を示すエラーとなり、新しいコンテナは作成されない。
Q13. 起動中の Docker コンテナ pg18 を強制的に削除するためのコマンドを答えよ。
答え: docker container rm -f pg18

3.3.1 定着確認（8問）

Q1. Docker で起動中のコンテナだけの一覧を表示するコマンドを答えよ。
答え: docker ps
Q2. Docker で停止中のものを含めてコンテナの一覧を表示するコマンドを答えよ。
答え: docker ps -a （または docker ps --all）
Q3. Docker の docker ps コマンドにおいて、 ps は何の略か答えよ。
答え: process status (プロセスの状態)
Q4. docker ps --all の --all を同じ意味の Short Option に書き換えたコマンドを答えよ。
答え: docker ps -a
Q5. docker ps -a の結果で、STATUS が Created となっていたコンテナの状態を答えよ。
答え: コンテナは作成済みだが、まだ一度も起動していない状態。
Q6. 作成後に起動していないコンテナ pg18 は、 docker ps と docker ps -a のどちらに表示されるか答えよ。
答え: docker ps には表示されず、 docker ps -a に表示される。
Q7. docker ps で1件も表示されなかった際、「コンテナが1つも存在しない」と判断してよいか。また確認用コマンドを答えよ。
答え: 判断してはいけない（停止中がある可能性がある）。 docker ps -a で確認する。
Q8. docker ps -a の結果で IMAGE が postgres:18.6 、 NAMES が pg18 であった。それぞれの意味を答えよ。
答え: postgres:18.6 は使用したイメージ名とタグ、 pg18 はコンテナの名前。

3.5.1 定着確認（5問）

Q1. 起動中コンテナ pg18 内で Bash を起動し、対話的に操作するためのコマンドを答えよ。
答え: docker container exec -it pg18 bash
Q2. docker container exec の役割と、対象コンテナが起動済みである必要があるか答えよ。
答え: 起動中のコンテナ内で指定コマンドを実行する。対象コンテナは起動済みである必要がある。
Q3. docker container exec -it pg18 bash の bash は何か。また実行場所はどちらか選べ。
【選択肢】❶ Windows 側 / ❷ pg18 コンテナ内
答え: BashはLinuxのシェル。実行される場所は ❷ pg18 コンテナ内。
Q4. -it の -i の Long Option とその役割を答えよ。
答え: Long Option: --interactive。標準入力を開いたままにし、キーボード入力できるようにする。
Q5. -it の -t の Long Option とその役割を答えよ。
答え: Long Option: --tty。仮想ターミナル (TTY) を割り当てる。

3.5.3 定着確認（5問）

【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（ホストOSのLinuxカーネルを共有している）。
Q5. コンテナ内で ls や cat が使えれば nano や vim も必ず使えるか答えよ。
【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（軽量化のため最小限のコマンドのみ含まれているため）。

3.5.5 定着確認（5問）

Q1. psql -U student -d playground の -U と -d の意味を答えよ。
答え: -U はユーザ名、 -d はデータベース名。
Q2. ユーザ student、DB playground に接続するための psql コマンドを答えよ。
答え: psql -U student -d playground

Q4. psql の -d オプションは、バックグラウンド実行のための指定である。この説明は適切か答えよ。
【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（-d はデータベース名の指定）。
Q5. psql の -U は、Unixドメインソケットで接続するための指定である。この説明は適切か答えよ。
【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（-U はユーザ名の指定）。

3.5.10 定着確認（7問）

【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（抽出結果に含めないだけでテーブル定義は変わらない）。

3.8.1 定着確認（8問）

Q1. 起動中コンテナ pg18 を停止するコマンドと正常停止時の応答を答えよ。
答え: コマンド: docker container stop pg18 / 応答: pg18
Q2. 停止中のコンテナ pg18 を削除するコマンドを答えよ。
答え: docker container rm pg18
Q3. 起動中コンテナ pg18 を強制削除(-f)を使わずに削除する手順を答えよ。
答え: 1. docker container stop pg18 実行後、2. docker container rm pg18 を実行する。
Q4. pg18 を削除せず停止した際、 docker ps と docker ps -a のどちらに表示されるか答えよ。

答え: 残っている（停止しただけではデータは保持される）。
Q6. docker container rm pg18 で削除したコンテナを docker container start pg18 で再起動できるか答えよ。
【選択肢】❶ 適切である / ❷ 適切ではない

【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（コンテナ削除でもイメージは残る）。
Q8. コンテナ削除（docker container rm pg18）により、保存していたボリュームのデータも削除されるか答えよ。
答え: 削除されない（コンテナとボリュームは独立して管理される）。

3.9.1 定着確認（20問）

Q1. プロンプトが root@e14852ebd977:/# のときの操作対象を選べ。
【選択肢】❶ Windows の PowerShell / ❷ Docker コンテナ内の Linux シェル / ❸ PostgreSQL の対話モード (psql)
答え: ❷ Docker コンテナ内の Linux シェル
Q2. どのコンテナからも使われていないイメージ postgres:18.6 を削除するコマンドを答えよ。
答え: docker image rm postgres:18.6
Q3. コンテナ名として使えるものをすべて選べ。使えないものの理由も答えよ。
【選択肢】A: pg18_test / B: pg18-test / C: pg18.test / D: _pg18
答え: A、B、C が使用可能。Dは先頭が英数字ではないため不可。
Q4. PostgreSQL の psql はどちらか選べ。また CLI の略を答えよ。
【選択肢】❶ データを管理するサーバープロセス / ❷ SQLを送信して結果確認するCLIクライアントツール
答え: ❷ SQLを送信するCLIクライアントツール。CLI = Command Line Interface。
Q5. ユーザ student、DB playground で psql 対話モードを開始するコマンドとオプションの意味を答えよ。
答え: psql -U student -d playground （-U: ユーザ名, -d: データベース名）
Q6. テーブルの「スキーマ」とはどのような情報か答えよ。
答え: どのような列を持ち、どのデータ型で扱うかといったテーブルの構造定義情報。
Q7. s_users テーブルを作成する CREATE TABLE 文と正常時の応答を答えよ。
答え: CREATE TABLE s_users (id INTEGER PRIMARY KEY, name TEXT NOT NULL, age INTEGER); （応答: CREATE TABLE）
Q8. CREATE TABLE 実行時に ERROR: relation "s_users" already exists と表示された意味を答えよ。
答え: 同名のテーブル等が既に存在している。
Q9. TRUNCATE TABLE s_users; 実行後、レコードとテーブルはどうなるか答えよ。
答え: レコードは全削除され空になる。テーブル構造自体は残る。
Q10. DROP TABLE s_users; 実行後、レコードとテーブルはどうなるか答えよ。
答え: レコード含めテーブルそのものが削除される。
Q11. SQL は改行や空白を文字列リテラルのなかも含めてすべて無視する。この説明は適切か答えよ。
【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（文字列リテラル内では改行や空白もデータとして意味を持つ）。
Q12. psql 対話モードを終了し Bash に戻るコマンドを答えよ。
答え: \q
Q13. コンテナ内の Bash を終了するコマンドと戻り先、コンテナの動作状態を答えよ。
答え: exit コマンド。PowerShellに戻る。コンテナ・PostgreSQLサーバーは動作を継続する。
Q14. hoge.sql の内容を標準入力で psql に送るコマンドと実行環境（PowerShell / cmd.exe）を答えよ。
答え: docker container exec -i pg18 psql -U student -d playground < hoge.sql （コマンドプロンプト cmd.exe で実行）。
Q15. ファイルリダイレクト（<）使用時、ファイル自体がコンテナにコピーされるか答えよ。
答え: コピーされない。ファイル内容が標準入力を通して psql に渡される。
Q16. リダイレクト時に -it ではなく -i のみを指定する理由を答えよ。
答え: 標準入力接続(-i)は必要だが、対話用仮想ターミナル割当(-t)は不要なため。
Q17. イメージが存在する際、「作成」と「起動」を1つで実行するコマンドを答えよ。
答え: docker container run
Q18. docker container run の -d オプションの意味とターミナルの状態を答えよ。
答え: デタッチドモード（バックグラウンド実行）。ターミナルは即座に操作可能に戻る。
Q19. docker container run で作成・起動した pg18 コンテナを停止した。同じコンテナを再び起動するときに使うコマンドを答えよ。また、同じ名前を指定して docker container run --name pg18 ... を再度実行した場合はどうなるか答えよ。
答え: 再起動コマンド: docker container start pg18 。再度 run を実行すると新コンテナを作成しようとするため、コンテナ名の重複エラーとなる。
Q20. 明示的にボリュームを指定せずに postgres:18.6 から作成したコンテナ pg18 に、テーブルやレコードを保存した。そのコンテナを停止して docker container rm pg18 で削除し、同じ手順・同じ名前で新しく作成すると、以前のDBデータは自動的に引き継がれるか答えよ。
答え: 自動的には引き継がれない（以前のボリュームにはデータが残っているが、新しいコンテナで自動再利用されないため）。

5.0.1 定着確認（9問）

Q1. PostgreSQL で使用される標準の通信ポート番号を答えよ。
答え: 5432番
Q2. Linux や macOS などの UNIX 系 OS において、同一ホスト内のプロセス間通信に使われ、PostgreSQL のローカル接続にも利用される仕組みを何というか答えよ。
答え: UNIXドメインソケット
Q3. Windows (ホストOS) 上のクライアントツールから、Docker コンテナ内の PostgreSQL サーバーに接続するときに使う通信方式を答えよ。
答え: TCP/IP 接続 (ポート通信)
Q4. Docker のコンテナ作成コマンドで、 -p オプションは何を設定するものか答えよ。また、コロン : で区切る2つのポート番号をどの順番で指定するか答えよ。
答え: ホスト側とコンテナ側のポートマッピングを設定するもの。「ホスト側のポート番号:コンテナ側のポート番号」の順。
Q5. Docker コンテナの作成時に -p 5432:5432 を指定した。この指定はどちら側の何番ポート同士をマッピングするものか答えよ。
答え: ホスト側の5432番ポートと、コンテナ側の5432番ポート。
Q6. Docker コンテナ内の PostgreSQL は5432番ポートで接続を受け付けている。ホスト側の15432番ポートから接続できるようにするため、コンテナ作成時に指定する -p オプションを答えよ。
答え: -p 15432:5432
Q7. PostgreSQL コンテナを -p 5433:5432 を指定して作成・起動した。Windows (ホストOS) 上のクライアントツールから、接続先ホストを localhost として接続するときに指定するポート番号を答えよ。
答え: 5433番（ホスト側のポート番号を指定する）。
Q8. ホスト側の5432番ポートは別のアプリが使用しているが、5433番ポートは空いている。コンテナ内の PostgreSQL が使う5432番ポートは変更せずに、ホスト側の5433番ポートから接続するための -p オプションを答えよ。
答え: -p 5433:5432
Q9. コンテナ内の PostgreSQL は5432番ポートで接続を受け付けている。ホスト側の5433番ポートから接続したいので、コンテナ作成時に -p 5432:5433 を指定した。この指定は目的に対して適切か答えよ。また、適切ではない場合は正しい指定を答えよ。
【選択肢】❶ 適切である / ❷ 適切ではない
答え: ❷ 適切ではない（指定が逆で、ホストの5432番とコンテナの5433番をマッピングしている）。正しくは -p 5433:5432 。
