第01回 データベース工学 定着確認（自己採点シート）

2.0.1 定着確認

Q1. データベースが行うデータの操作について、「蓄積・管理」以外の例を3つ答えよ。
答え: 検索、更新、削除、集計、加工などから3つ
Q2. データそのものと、それを管理する仕組みを区別する場合、「DB」と「DBMS」はそれぞれ何を指すか答えよ。
答え: DB はデータそのもの、DBMS はそれらを管理する仕組みやソフトウェアを指す。
Q3. 「データベース」という言葉が指すものは、非情報分野でもソフトウェア開発の分野でも常に同じであり、文脈によって使い分けられることはない。（適切 / 適切ではない）
答え: 適切ではない
Q4. ソフトウェア開発の説明で、DBMS を使わずに CSVファイル を読み込むだけの処理を「データベースから情報を取得する」と表現すると、どのような誤解を与えるか答えよ。
答え: 単なるファイルの読み込みではなく、DBMS を利用してデータを管理・取得していると受け取られるおそれがある。
Q5. DBMS の役割はデータを保存することだけであり、ユーザーごとのアクセス制御や障害時復旧は、DBMS が標準的に備える機能には含まれない。（適切 / 適切ではない）
答え: 適切ではない
Q6. DBMS とは何の略語か英語で答えよ。
答え: Database Management System
Q7. DBMS の日本語での名称を答えよ。
答え: データベースマネジメントシステム、データベース管理システム
Q8. PostgreSQLなどのサーバ型DBMSが備えている機能として「適切ではないもの」はどれか。（❶ユーザー制御 ❷ネットワーク ❸整合性 ❹プログラム自動作成 ❺障害復旧 ❻ウイルス対策）
答え: ❹, ❻
Q9. 一般に「DBMS とは見なされないもの」はどれか。（❶SQLite3 ❷PostgreSQL ❸Oracle ❹Excel ❺Access ❻SQLAlchemy ➐Pandas ❽Prisma）
答え: ❹, ❻, ➐, ❽
Q10. 開発現場において「データベースのバージョンアップ」という表現が指しているものはどれか。（❶データ更新 ❷DBMSソフトウェア更新 ❸形式変更 ❹データ増加）
答え: ❷（DBMS ソフトウェアを新しいバージョンに更新すること）
Q11. 非情報分野における広い意味においても「データベース」とは基本的に電子データを指すため、紙の電話帳や国語辞典はデータベースとは見なさない。（適切 / 適切ではない）
答え: 適切ではない
Q12. 非情報分野では、一定の形式や構造に従って整理された CSVファイル や JSONファイル も「データベース」と呼ぶことがある。（適切 / 適切ではない）
答え: 適切である

3.1.1 定着確認

Q1. プロセス (プログラム) の終了後も必要な情報を保持し、次に起動したときにも利用できるように、SSD や HDD などへ保存することを何というか。漢字3文字で答えよ。
答え: 永続化
Q2. プロセス (プログラム) の終了後も情報を利用したい場合、そのプログラムの実行中のメモリに保持しておくだけでは不十分な理由を答えよ。
答え: プロセスの終了時に、そのプロセスが使っていたメモリ領域は解放される。再び起動しても、以前の変数の値は自動的には復元されないため。
Q3. アプリで入力した情報をファイルに保存した。アプリを終了し、再び起動したときに、その保存済みの情報を処理に利用するためには、どのような処理が必要か答えよ。
答え: 保存したファイルから情報を読み込み、アプリで利用できる状態にする処理。
Q4. データの保存が完了しなかったり、保存済みのデータが利用できなくなったりする原因となる障害の例を2つ答えよ。
答え: 例: 記憶装置の故障、保存処理の途中でのプログラムの異常終了。
Q5. データを永続化しているアプリでも、データの重要度に応じてバックアップを設計する必要がある理由を答えよ。
答え: 永続化しても、記憶装置の故障などで元のデータを失う可能性があるため。
Q6. PostgreSQL は、標準的な構成では OS のファイルシステム上のファイルにデータを保存する。（適切 / 適切ではない）
答え: 適切である

3.2.1 定着確認

Q1. JSON とは何の略語か英語で答えよ。
答え: JavaScript Object Notation
Q2. CSV とは何の略語か英語で答えよ。
答え: Comma Separated Values
Q3. 入力された名前を変数に保持して画面に表示するだけのプログラムがある。この名前をプログラムの終了後も保持し、次に起動したときに利用するためには、どのような処理が必要か答えよ。
答え: 名前をファイルや DBMS などを用いて永続化し、次に起動したときに読み込む処理が必要。
Q4. アプリの設定を起動時に読み込む用途や、集計結果を別のシステムに渡す用途でも、JSON や CSV のファイルを使う方法は不適切であり、必ず DBMS を利用しなければならない。（適切 / 適切ではない）
答え: 適切ではない
Q5. 複数のデータ更新をひとまとまりとして扱い、そのまとまり全体を反映するか、全体を取り消すかを保証する仕組みを何というか。カタカナで答えよ。
答え: トランザクション
Q6. 注文の記録 (処理A) と在庫の更新 (処理B) を行うプログラムで、処理Aが完了した直後にプログラムが停止し、処理Bが実行されなかった。このような不整合を防ぐため、処理A と 処理B をどのような単位の処理として扱う必要があるか答えよ。
答え: 処理Aと処理Bをひとまとまりとして扱い、処理の一部だけが反映された状態が残らないよう、両方を反映するか、両方とも反映しないようにする必要がある。
Q7. 「注文を記録する」と「在庫を減らす」を1つのトランザクションにまとめた。処理が完了したとき、または取り消されたときの最終的な結果として、適切なものを全て答えよ。（❶両方反映, ❷注文のみ反映, ❸在庫のみ反映, ❹両方取り消し）
答え: ❶, ❹
Q8. あるトランザクション全体を取り消すと、そのトランザクションの開始前から保存されていたデータも含めて、データベース内の全データが削除される。（適切 / 適切ではない）
答え: 適切ではない（取り消す対象は、そのトランザクションで行った変更のみ）。
Q9. トランザクションを利用できる DBMS を導入すれば、「注文の記録」と「在庫の更新」をまとめるべきかどうかを、DBMS がアプリの業務内容から自動的に判断してくれる。（適切 / 適切ではない）
答え: 適切ではない（アプリの要件に合わせて人間が設計する必要がある）。
Q10. データの更新を「全て反映するか、全て取り消すか」のまとまりとして扱うことは、処理の途中で失敗した場合に、どのような問題を防ぐために役立つか答えよ。
答え: ひとまとまりとして扱うべき更新の一部だけが残り、関連するデータの整合性が失われる問題を防ぐために役立つ。
Q11. ある商品の在庫数が 10 個、記録済みの注文が 4 件ある。「購入注文1件追加」と「在庫数1減」を1つのトランザクションとして実行したが途中で失敗し取り消された。取り消し後の在庫数と注文件数を答えよ。
答え: 在庫数は 10 個、注文は 4 件。
Q12. 口座Aの残高 3,000 円、口座Bの残高 1,000 円から「口座Aから500円引き、口座Bに500円加える」トランザクションを確定した。確定後の各口座残高を答えよ。
答え: 口座Aは 2,500 円、口座Bは 1,500 円。

3.4.2 定着確認

Q1. サーバの設定ファイルに対して「管理者X」が編集して保存した後、古い状態のまま開いていた「管理者Y」が編集して保存した結果、「管理者X」の内容が消失した。この現象を何と呼ぶか英語で答えよ。
答え: Lost Update
Q2. アプリAとBが同じCSVを読み込み、Aは住所、Bは成績を変更してファイル全体を書き戻す。更新の消失について最も適切な説明を選べ。
答え: ❸（古い内容を含むファイル全体を書き戻すことで、他方の更新が失われる可能性がある）
Q3. 複数のアプリによるファイルの更新が互いに干渉しないよう、ロックなどを使ってアクセスを制限する仕組みを何というか。
答え: 排他制御
Q4. ファイル全体への排他ロック中、教員Aが「学生X」の住所を編集している際、教員Bは同じファイルの「学生Y」の成績を更新できるか。理由とともに答えよ。
答え: 更新できない。ロックの対象がファイル全体なので、別の学生や項目への更新でもロック解除を待つ必要があるため。
Q5. アプリAとBが保存する瞬間だけ排他ロックを取得してファイル全体を上書きする方法で Lost Update を防げるか。理由とともに答えよ。
答え: 防げない。書き込み自体を順番に実行しても、後から保存するアプリが古い内容を保持していれば上書きされるため。
Q6. CSV/JSONを直接読み書きする方法と、DBMSを利用する方法の説明として最も適切なものを選べ。
答え: ❷（DBMSを利用する場合、検索、更新、トランザクション、同時アクセス制御などをDBMSに任せることができる）
Q7. ファイル直接読み書きと比べて、DBMS利用が特に有効となる要件の例を2つ答えよ。
答え: 例: 複数のユーザやプログラムが同じデータを同時に参照・更新すること、複数のデータを一連の処理として整合性を保ちながら更新すること。

3.5.1 定着確認

Q1. ファイルやフォルダに対して、誰が操作を行えるかを定める「アクセス権」を何というか。カタカナで答えよ。
答え: パーミッション
Q2. 教員Xにファイル全体のアクセス権を与えつつアプリ画面で編集範囲を制限した対策について、最も適切な説明を選べ。
答え: ❷（アプリ上では制限できるが、テキストエディタ等で直接編集できる経路が残っているため変更される可能性がある）
Q3. 教員XのOS権限でファイル書き込みを禁止した場合、同じ権限で動く成績管理アプリからの書き込みはどうなるか。
答え: 成績管理アプリからも書き込めなくなる。
Q4. ファイル全体の読み取り権限を与えたまま、アプリ画面上で一部項目を非表示にすることで閲覧制限を実現できるか。
答え: 実現できない。ファイル全体の読み取り権限があれば直接開いて読み取ることができるため。
Q5. 担当科目の成績だけを変更させたい場合、アプリ画面の制限以外にどのような点を確認する必要があるか。
答え: テキストエディタなど、アプリを経由せずにファイルを直接書き換えられる経路が残っていないか確認する。

6.1.1 定着確認

Q1. RDBMS に対するクエリを記述するために使用される言語をアルファベット3文字で答えよ。
答え: SQL
Q2. RDB において、一般にテーブル（表）の「列」を指す語をカタカナで答えよ。
答え: カラム、フィールド、アトリビュート (属性)
Q3. RDB において、一般にテーブル（表）の「行」を指す語をカタカナで答えよ。
答え: レコード、タプル
Q4. 社員テーブル (5項目, 7人分) のカラム数とレコード数を答えよ。
答え: カラム数は5、レコード数は7。
Q5. birthday という項目と、社員1人分の1行はそれぞれ「カラム」「レコード」のどちらか。
答え: birthday はカラム、社員1人分の1行はレコード。
Q6. RDBにおいて、複数のテーブルを関連付けて結合する操作をアルファベットで答えよ。
答え: JOIN
Q7. 社員テーブルと部署テーブルを結びつける際、どのカラム同士を対応させればよいか。
答え: ❷（employees.department_id と departments.id）
Q8. 社員「品質 守」(department_id: 2) に対応する部署名を答えよ。
答え: 曖昧戦略部
Q9. 部署名を社員レコードごとに重複保存し、部署名変更時に一部だけ修正した場合どんな問題が起こるか。

Q10. 社員テーブルとは別に部署テーブルを設ける構成のメリットとして最も適切なものを選べ。

Q11. 部署一元管理設計がデータ不整合を防ぎやすい理由を述べた説明は適切か。
答え: 適切である（部署テーブルの該当レコードのみ更新すればよく、更新漏れを防げるため）。

Q5. PostgreSQLで扱えるデータ型について最も適切な説明を選べ。
答え: ❷（数値・文字列に加え、配列や JSON/JSONB 型など多様な型を扱える）
Q6. PostgreSQLのSQLを別RDBMSへ移す際、そのまま動くとは限らないという説明は適切か。
答え: 適切である

Q10. 動作中の SQLite データベースのバックアップとして最も適切な方法を選べ。
